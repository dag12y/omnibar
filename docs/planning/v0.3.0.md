# v0.3.0 proposal: Quick productivity

Status: M30 Scratchpad implemented; M31–M35 remain planned.
Baseline: released v0.2.0, including M29 saved window arrangements.

## Release outcome

Make Omnibar useful for quick notes, timed work, and finding everyday actions
from one panel. Keep the current Go/Quickshell architecture, existing desktop
features, local storage, and Arch distribution workflow.

The proposed release contains four visible improvements: Scratchpad, Timers,
expanded Search, and a navigation/settings pass. Complete them in the milestone
order below, followed by stabilization and release. Milestone numbers are
used by this plan; completion is recorded in MILESTONES.md.

## M30 — Scratchpad (complete)

Add a Notes page for plain-text notes:

- Create, rename, edit, search, pin/unpin, and delete notes.
- Autosave after a short typing pause; clearly show Saving, Saved, or Unsaved.
- Preserve notes across panel close, UI restart, and backend restart.
- Copy a note through the existing clipboard.write permission.
- Confirm deletion and keep unsaved editor text available after write failure.
- Start with a proposed limit of 100 notes, 32 KiB per note, and 2 MiB total.
  Report limits explicitly rather than silently truncating text.

Use private, versioned storage in Omnibar's XDG data directory, atomic writes,
strict input bounds, opaque note IDs, and revisions to reject stale edits from
multiple clients. Preserve unreadable/corrupt files and expose a recovery error.
An external editor, Markdown renderer, attachments, cloud sync, and export/import
are outside this release. Specify narrowly scoped module permissions in an ADR
before coding; app-owned data must not require arbitrary filesystem access.

Done when real UI editing, autosave/reopen, failed-write retention, deletion,
permission denial, bounds, stale edits, and restart recovery are verified.

## M31 — Timers

Add named countdown timers for quick reminders and focused work:

- Presets of 5, 15, 25, and 60 minutes, plus a custom duration up to 24 hours.
- Start, pause, resume, cancel, and dismiss completed timers.
- Show remaining time and a compact active-timer indicator in the panel.
- Continue while the panel is hidden or the UI is restarted.
- Persist running deadlines and paused remaining time for backend restart.
- On resume/restart after a deadline, show the timer as completed once.
- Show completion in Omnibar and request a desktop notification when the desktop
  notification service is available. Notification failure must not lose the result.
- Bound the initial implementation to 10 unfinished timers.

The backend owns timing. Define suspend/resume, wall-clock adjustment, and
restart behavior explicitly before implementation. Use monotonic timing during
an uninterrupted run, reconcile persisted deadlines after restart, and prevent
repeated completion alerts. Avoid constant disk writes or background UI polling.
This is a countdown feature; recurring schedules, calendars, Pomodoro analytics,
and a replacement notification daemon remain later work.

Done when hidden-panel operation, UI/backend restart, expiry, pause/resume,
suspend/clock-change handling through a test clock, and unavailable notification
service behavior are covered. Desktop checks must use synthetic timers.

## M32 — Expanded Search and explicit actions

Extend the current app/window Search rather than adding another command bar:

- Find notes by title/content and open the chosen note by its stable ID.
- Find saved window layouts by name and offer an explicit Restore action.
- Offer a small fixed catalog of actions: open a page, start a timer preset,
  and start a Keep Awake preset.
- Label result kinds and actions clearly: Open note, Switch, Launch, Restore,
  or Start. Retain keyboard selection across source refreshes.
- Keep each source's permission/error state independent. Existing app/window
  search must remain usable when Notes or Timers is disabled.
- Preserve bounded results, plain-text snippets, cache cleanup, and no search
  history. Notes stay local and are not logged.

Actions are typed backend operations with validated parameters. Search must not
run arbitrary shell commands or reinterpret failed window switching as launch.
Restoring a layout keeps its existing matching/topology/partial-failure rules.
Document what Enter does for each result kind and when the panel stays open.

Done when each result dispatches the exact operation, selected note navigation
works, denied/stale targets remain safe, partial sources work, and keyboard/UI
regressions pass in the private desktop harness.

## M33 — Navigation and settings

Make the larger panel easy to navigate:

- Replace the growing rows of page buttons with a compact page picker or
  grouped navigation that works on small displays and with the keyboard.
- Keep Search easy to reach and preserve Ctrl+K within the focused panel.
- Add Settings with module availability, granted/missing permissions, version,
  and backend connection status, plus concise instructions for enabling a feature.
- Offer local UI preferences for the landing page and visible navigation items.
- Keep the current Omarchy theme integration and show consistent empty, loading,
  denied, unsaved, and error states across the new pages.
- Document omnibar-toggle and page-opening IPC so hidden/running UI behavior is
  clear. Do not install or replace the user's desktop keybindings automatically.

Hiding a navigation item does not revoke permissions or stop an active timer.
Capability grants remain explicit config changes; this scope does not include
an automatic permission-grant mechanism or a general-purpose config editor.

Done when all pages remain reachable with keyboard navigation, expanded content
scrolls into view, small displays work, settings report actual backend state,
and hidden/disabled items do not break active features.

## M34 — Stabilization

Reserve a dedicated pass before tagging:

- Preserve existing configs, favorites, and saved layouts through upgrades.
- Test private notes/timer storage permissions, corruption handling, interrupted
  writes, size limits, and failed-save recovery.
- Check requests in flight during hide, reconnect, page changes, and shutdown;
  discard stale responses without losing acknowledged user data.
- Run Go vet/race checks, QML checks, real new-feature UI checks, and regressions
  for apps, windows, controls/layouts, previews, audio, clipboard/shelf, and Awake.
- Check hidden-panel work: no unnecessary polling, capture, or storage writes.
- Verify focus restoration, wrapping, scroll behavior, and accessible labels.
- Fix regressions within this scope; move additional feature requests to a later
  release rather than extending the candidate indefinitely.

Done when required checks pass with no known note-loss, permission-bypass,
misdirected action, or duplicate-timer-alert issue. Record platform limits and
any remaining non-blocking issues in the release verification document.

## M35 — v0.3.0 release

- Update version, changelog, usage docs, capability examples, and release notes.
- Build and test an x86_64 Arch package from the exact tagged source archive.
- Verify extracted-package UI and isolated install/upgrade/reinstall/downgrade/
  uninstall/reinstall transactions, preserving notes, timers, config, favorites,
  layouts, and state files and their permissions.
- Install the final package locally and confirm the packaged backend/UI and
  installed-file integrity.
- Publish source, package, verified PKGBUILD, and SHA256SUMS; verify uploaded hashes.
- Report architecture/reboot/platform coverage honestly; do not imply untested
  aarch64 support has been validated.

The release is complete when these results are recorded and the published,
installed package matches the tested source. Tag only after feature scope and
stabilization criteria are met.

## Deferred scope

Color picking, OCR/QR, screenshots/recording, media conversion, GPU/history
monitoring, Bluetooth/display/package controls, input customization, cloud sync,
and a Dynamic Island are candidates after v0.3.0. Each deserves its own design
and desktop integration verification; they are not dependencies of this release.

## Next implementation step

Start M31 with the timer state machine and timing/persistence ADR, including
suspend, clock-change, restart, and notification behavior. M30's editor, storage,
and failure/restart checks are complete. Finish each subsequent milestone before
moving to the next, keeping builds usable throughout. Establish the new
navigation before adding further pages beyond Notes and Timers.
